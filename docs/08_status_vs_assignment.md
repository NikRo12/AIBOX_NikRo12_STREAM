# Статус относительно ТЗ

**Область этого репозитория: STREAM (пропускная способность памяти) на
AIBOX-K3 (SpacemiT K3, RISC-V 64) — только один из 2-3 участников
группы и одна из двух платформ ТЗ.** GEMM/compute-bound (§5, §7, §8) —
часть другого участника, не здесь. Orange Pi 5 Plus и Banana Pi — не
измерялись здесь.

## Ответы на контрольные вопросы §9 — в части STREAM/AIBOX-K3

| Вопрос ТЗ | Ответ | Источник |
|---|---|---|
| Какая доля теоретического пика достигается? | Максимум ~35% (X100, 8 потоков, 17916.7/51200 MB/s) | [`03_bandwidth_results.md`](03_bandwidth_results.md) |
| При каком числе потоков насыщается память? | Не зафиксировано строго в диапазоне 1-8 — рост продолжается до 8 потоков, прирост на переходах не монотонно убывает (1→2: +2208.7, 2→4: +1852.8, 4→8: +3662.3 MB/s) | [`03_bandwidth_results.md`](03_bandwidth_results.md#3-scaling--рост-с-числом-потоков) |
| Где границы кэшей? | X100: L1D ~64 КБ, L2 ~3.5-4 МБ (излом не зависит от числа потоков → вероятно общий на кластер, не подтверждено `lscpu -C`). A100: граница L2 не проявляется на измеренном диапазоне — открытый вопрос | [`01_hardware_passport.md`](01_hardware_passport.md#3-кэш-иерархия) |
| Насколько эффективно используются RVV? | На X100 упирается в аппаратный лимит 2 порта×128 бит/такт независимо от LMUL (подтверждено perf с точностью 0.04%); на A100 не измерено. NEON/SVE — не относится (это RISC-V плата) | [`04_perf_profiling.md`](04_perf_profiling.md), [`05_root_cause_analysis.md`](05_root_cause_analysis.md) |
| Когда GEMM становится compute-bound? | Не в этом репозитории (GEMM — часть коллеги) | — |
| Какие библиотеки лучше оптимизированы? | Не в этом репозитории | — |
| Какие результаты реальны, а какие — артефакты измерений? | Два разобранных примера: FP16 ×88 «отставание» — артефакт конфигурации сборки (отсутствие `zvfh`), исправлено; разрыв Copy/Scale внутри кэша — реален, объясняется Roofline-переходом, не брак измерения | [`06_anomalies_and_fixes.md`](06_anomalies_and_fixes.md) |
| Какая платформа быстрее и в каких задачах? | Не отвечено — нет данных по Orange Pi/Banana Pi. Внутри AIBOX-K3: X100 быстрее A100 на арифметике на 1 потоке (2-3×), разрыв почти исчезает на 8 потоках | [`05_root_cause_analysis.md`](05_root_cause_analysis.md) |

## Ближайшие шаги (по убыванию влияния на итоговую сдачу)

1. Измерения на Orange Pi 5 Plus (и опционально Banana Pi) — единственный
   пункт, без которого невозможен раздел сравнения платформ ТЗ §9.
2. Сырой вывод команд паспорта платформы (`lscpu -C`, `/proc/cpuinfo`,
   `dmesg`, `cpupower`) — быстро, данные для расчётов уже есть.
3. `perf stat`/`perf annotate` на A100 — закрывает два открытых вопроса
   одним шагом.
4. Дизассемблер/perf для гипотезы fp32 vs fp64.
5. Починить `scaling --target-cluster mixed`.
6. Пересобрать/перемерить `cache_sweep` для fp16 с исправленным `zvfh`.

Полные формулировки каждого пункта — [`07_open_questions.md`](07_open_questions.md).
